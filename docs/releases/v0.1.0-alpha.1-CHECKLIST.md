# v0.1.0-alpha.1 Candidate Checklist

Status: **Repository preparation in progress**.

This checklist is scoped to the first Alpha candidate. It complements, but does not replace, the global [Release Checklist](../RELEASE_CHECKLIST.md).

## Automated repository gates

- [ ] latest candidate commit is on `main`;
- [ ] Windows / macOS / Linux CI is green;
- [ ] Interoperability Gate is green;
- [ ] Docs / Sheets / Slides performance gates are green;
- [ ] Native Performance and Native Integration gates are green;
- [ ] Release Hardening Gate is green;
- [ ] prerelease version validation accepts `0.1.0-alpha.1` against workspace `0.1.0`;
- [ ] Windows, macOS and Linux prerelease-labeled packages build successfully;
- [ ] SHA-256 manifests and traceability metadata are generated.

## Publisher / reference-machine gates

These cannot be truthfully completed by repository CI alone:

- [ ] perform a 2+ hour interactive editing soak on a reference machine;
- [ ] test install/uninstall of the produced packages on release machines;
- [ ] verify crash recovery interactively;
- [ ] review the release notes and known limitations;
- [ ] decide whether unsigned/unnotarized Alpha artifacts are acceptable for publication, or provide signing/notarization credentials;
- [ ] confirm the project distribution/license decision for this Alpha;
- [ ] create and push the final `v0.1.0-alpha.1` tag only after the above decisions.

## Publication behavior

The release workflow treats tags containing a prerelease suffix (for example `-alpha.1`) as GitHub **prereleases**. A manual workflow dispatch only builds downloadable artifacts and does not publish a GitHub Release.
